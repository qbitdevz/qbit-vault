Proposal (verbatim): "1. **Value-free diagnostics for the agent**, for example a `secret_check` tool (or `secret_list` fields) that answers without returning values: length, and whether a value looks like the declared kind (email, URL, JWT, PEM key…) via an optional `format` metadata field; whether two named secrets hold the same value; whether the value is empty, whitespace-padded, or a common placeholder (`change-me`, `TODO`, `xxx`…). 2. **Skill update** for \"When a service rejects the credential\": before proposing `replace`, run those checks on *every* secret the call used (identifier fields such as emails or usernames too, not only the password), and report what they show. 3. **Replace dialog safety**: warn when the new value equals the current one or another secret in the same layer, and keep the previous value recoverable for a short time (or let the user confirm the old one is discarded), so a replace on a wrong hypothesis does not destroy the only copy. 4. Optional: record the last successful use of a secret (time and command), so the agent can tell \"this worked before\" from \"this never worked\"." Security (verbatim): "The checks return booleans, lengths and format guesses, never values. Equality checks between secrets leak one bit per pair, only for secrets the agent is already granted. Keeping the previous value on replace needs the same at-rest protection as current values and a bounded retention."
