## Assumptions (not requested; to be confirmed by the owner)

- A1. S4/S5 apply to the PowerShell dialog (Windows and WSL), the only window qbit-vault draws itself. zenity, kdialog and osascript are stock dialogs without a controllable minimize button or reveal toggle; they are left as they are and the docs say so.
- A2. S5: the value stays hidden by default; the toggle only shows it while switched on. Visible text fields keep their current behavior.
- A3. S7: a minimized dialog still ends after `QBIT_VAULT_PROMPT_TIMEOUT`.
- A4. S7 (T6): `secret_exec_stop` is not literally requested: the owner chose "start/status" (L2). It is there because a job that cannot be stopped would repeat the issue's "left test data behind" problem (a stuck build, a server the command started, a job that holds an injected value until its `timeout_ms`). It adds no new power: it uses the runner's existing tree kill, and a job also ends by itself with `timeout_ms` and with the server.
- A5. S8.1 (T7): the issue's optional `format` metadata field is not added: it would change the stored record format (and every consumer of it), so `looks_like` is a guess from the shape of the value only, never compared with a declared kind. Adding a declared format later is a separate, owner-approved change to the stored format.
